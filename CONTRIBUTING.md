# Contributing

## Choose the right change

1. Search `catalog/catalog.json` and `skills/` for the intended trigger.
2. Improve an existing skill when the trigger and workflow overlap.
3. Add a skill only when it has a distinct **trigger → outcome → verification** contract.
4. Preserve upstream attribution and license metadata.

## Skill contract

Every `SKILL.md` must:

- start with YAML frontmatter at byte zero;
- define lowercase `name` and a trigger-specific `description`;
- explain an ordered, executable workflow;
- include observable completion or verification criteria;
- keep long tables/examples in `references/`;
- include referenced scripts, templates, and assets in the same skill tree;
- avoid hardcoded credentials, host-specific secrets, generated caches, and binary build artifacts.

Recommended frontmatter:

```yaml
---
name: example-skill
description: Use when <distinct trigger>; produces <artifact or verified outcome>.
version: 1.0.0
license: MIT
metadata:
  category: example
  upstream: https://example.invalid/project
---
```

## Validate

Run after the final edit:

```bash
py -3 tools/canon.py catalog
py -3 tools/canon.py validate --baseline config/quality-baseline.json
py -3 tools/canon.py catalog --check
py -3 -m unittest discover -s tests -v
git diff --check
```

Do not update `config/quality-baseline.json` merely to make a regression green. Review the changed metric and reduce the debt first. If a deliberate import increases a warning metric, record why in the commit and regenerate the baseline explicitly.

## Duplicate names

This repository preserves several upstream packs, so legacy duplicate names exist. New duplicate declarations are rejected by the quality baseline. If a duplicate is unavoidable, make its path and package identity clear and document which entrypoint is canonical.

## Generated files

`catalog/catalog.json` and `catalog/CATALOG.md` are generated by `tools/canon.py`. Commit both whenever skill metadata or domain rules change.

## Change hygiene

- Keep one concern per commit.
- Do not commit `__pycache__`, `.pyc`, editor state, captures, dumps, credentials, or private samples.
- Run a secret scan before publishing imported packs.
- Preserve executable bits on scripts where the upstream workflow relies on them.
- Report exact validation commands and results; do not claim checks that were not run.
